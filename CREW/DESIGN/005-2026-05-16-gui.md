Summary:
gui.py is a large monolithic Tk-based GUI module. It mixes UI layout, business logic, auto-import/execution of scripts, side-effectful startup actions (pip installs/prints), and sample file generation.

Recommendations (retain functionality):
1. Break gui.py into submodules: widgets/, menus.py, dialogs.py, startup.py, settings.py so each file is testable.
2. Move auto-install/side-effect behavior out of import time. Provide an optional bootstrapper invoked explicitly by the launcher.
3. Remove prints; use logging consistently. Make long-running tasks run in background threads with clear cancellation paths.
4. Replace in-module sample script creation with a one-time CLI setup step or provide a --bootstrap flag.
5. Add heavy typing, dataclasses for state, and small pure helpers for testability. Ensure methods are small and focused.
6. Centralize theme/colors into Config and avoid magic constants spread across file.
7. Add end-to-end GUI tests where practical (pytest + tkinter headless mocks) and unit tests for helpers.
8. Enforce PEP8 (flake8/ruff) and break large functions into smaller ones.
